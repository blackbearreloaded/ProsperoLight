# Повторяемая проверка плавности

## Быстрый старт

1. Примените настройки стрима на PS5, подключитесь к Desktop. Браузер ПК должен находиться на транслируемом дисплее, который работает в 120 Гц или выше.
2. Откройте `index.html` двойным щелчком в браузере ПК. Укажите совпадающие кодек/FPS/режим/HDR/VSync. Эти поля — только подписи отчёта, они **не меняют** настройки ProsperoLight или Vibepollo.
3. Нажмите «Начать в полном экране». Дождитесь конца 90 секунд. Страница автоматически чередует движение и полностью неподвижные участки; видимые счётчики на статике также заморожены.
4. Нажмите Escape, скачайте JSON. В нём будут настройки прогона, фазы и частота браузера. Предупреждение о низкой частоте браузера означает, что ПК не создавал достаточного движения для теста заданных FPS.
5. Выйдите из стрима. Перед следующим запуском подождите 15 секунд.

Логи PS5 можно автоматически сохранять на любом компьютере в LAN с Python 3:

```bash
python collect.py --watch --host 192.168.1.137 --output pacing-logs
```

Адрес замените при необходимости. Скрипт использует анонимный FTP, сохраняет завершённые сессии в разные папки и работает без дополнительных библиотек. Дождитесь сообщения `Saved` после завершения стрима. Ctrl+C останавливает сборщик. Без `--watch` он скачает один текущий снимок. Сам сборщик не запускает и не останавливает стрим.

## С чего начать

Первый этап — **9 прогонов**, каждый по 90 секунд: **49, 50 и 51 FPS** для **PyroWave, HEVC и H.264**. Настройки: 1080p SDR, Paced+VRR, VSync On, системный VRR PS5 On. PyroWave 200 Mbps, HEVC/H.264 20 Mbps. На время первого этапа «Apply to Unsupported Games» оставьте Off; параметры ТВ не меняйте.

| Исходные FPS в движении | Цель VRR-вывода |
|---:|---:|
| 30 | около 60 Гц |
| 40 | около 80 Гц |
| 45 | около 90 Гц |
| 48 | около 96 Гц |
| 49 | около 98 Гц |
| 50 | около 100 Гц |
| 51 | около 102 Гц |
| 75 / 90 / 100 / 120 | около 75 / 90 / 100 / 120 Гц |

Это цели планировщика при устойчивом входящем FPS, не обещание показаний ТВ. Кадры повторяются, а не интерполируются. На статике хост может снижать FPS примерно до 16, и тогда повторов станет больше (~64 Гц). Возврат к движению должен возвращать нормальную частоту без залипания. Краткое время на определение новой частоты допустимо.

Полный перечень **49 прогонов** — `matrix.csv`. Колонки для наблюдений оставлены пустыми. Сначала пройдите девять основных случаев A49/A50/A51, затем A45/A48, B, C, D, E, F. F3 для каждого кодека запускайте сразу после соответствующего F2. В группах F следуйте значениям `ps5_vrr` и `vsync` в CSV, затем восстановите основные настройки. После матрицы полезно провести 30–60 минут в игре при 4K120 HDR Paced+VRR.

В Paced частота фиксирована: до 60 FPS — 60 Гц, выше — 120 Гц. При 45 FPS на 60 Гц интервалы неизбежно чередуются, поэтому не следует ожидать равномерности VRR 45→90. При Paced+VRR VSync принудительно включён; после перехода в Paced должен восстанавливаться сохранённый выбор VSync.

## Что записывать

ID строки CSV, мерцание/рывки, частоту ТВ на движении, статике и повторном движении; сохраните JSON страницы и папку логов. Во время прогона не открывайте меню PS5 и не сворачивайте браузер. Страница — SDR-сцена, даже при HDR-стриме; она не проверяет правильность HDR-цветов.

Главные признаки ошибки: стойкое ограничение 60 при входящих 90/120 FPS, быстро и постоянно растущие stale в устойчивом движении, разное поведение холодного запуска и возврата из статики, вылет/зависание. Отдельные пропуски при переходах отметьте в CSV. Низкие FPS из-за загрузки декодера нужно отделять от ошибок вывода; для этого первый этап проходит в 1080p. H.264 4K120 отдельно остаётся тяжёлым режимом.

JSON страницы измеряет браузер **ПК**, а не вывод PS5. Логи PS5 измеряют программные наблюдения счётчиков, а не физический HDMI. У PyroWave `shown` включает повторы, у native H.264/HEVC — уникальные картинки, поэтому абсолютные счётчики напрямую не сравниваем. Общие строки `VRR cadence` показывают FPS источника, множитель повторения и целевую частоту. Длительные задержки на этапе подключения не включайте в оценку ровности уже работающего стрима.

Абсолютно нулевые пропуски не обязательны: запрошенные 120 FPS и номинальные 119,88 Гц немного различаются. Небольшие потери из-за этого, джиттера источника или нагрузки декодера нужно отделять от прежнего ограничения вывода около 60 FPS.

### Автоматическое сохранение отчётов

При открытии страницы на `http://192.168.1.191:9075/` отчёт после каждого прогона автоматически отправляется на сервер. Дождитесь надписи «Отчёт сохранён на сервере». Скачивать и пересылать JSON не нужно. При ошибке отправки остаётся кнопка ручного скачивания. Открытая с диска копия страницы не имеет серверного приёмника.

Для собственного LAN-сервера: `python3 server.py --reports /absolute/path/outside/webroot`. JSON сохраняются отдельно от публичной страницы; приёмник принимает до 2 MiB на отчёт. Это инструмент для доверенной локальной сети, без авторизации. Отчёты содержат настройки теста, браузер и временные интервалы, но не изображение рабочего стола.

Около запрошенной частоты колебания меток хоста до ±5% больше не меняют множитель повторов. Реальное снижение FPS на статике по-прежнему обрабатывается. Для повторной проверки: каждый кодек в 49, 50 и 51 FPS, 1080p SDR, Paced+VRR, VSync On; PyroWave 200 Mbps, H.264/HEVC 20 Mbps.
